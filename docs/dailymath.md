# DailyMath API

기존 quiz Next.js 서버와 Railway MySQL을 사용합니다. 공개 주소는 `https://minguu.dev`이며 앱에는 `DAILYMATH_API_URL`만 설정합니다. MySQL 연결 정보는 서버의 기존 `MYSQL_URL`에 둡니다. PC에 DB 서버를 설치하지 않습니다.

## 인증과 신뢰 범위

2026-09-19 사용자가 클라이언트 학번을 신뢰하는 방식을 명시적으로 선택했습니다. 다른 사람의 학번으로 API를 직접 호출하면 그 학번의 학습 기록을 조회·변경할 수 있다는 제한도 별도로 승인했습니다. 보안이 필요한 서비스의 학교 본인 인증으로 사용하면 안 됩니다.

정상 앱은 송죽학사에 로그인한 뒤 기기에서 내정보 페이지의 학번을 확인합니다. 학교 비밀번호·JSESSIONID·자동 로그인 seed는 quiz 서버에 보내지 않습니다.

- `POST /api/dailymath/auth`: JSON `{ "student_id": "26101" }`. 서버는 5자리 형식을 검사하고 SHA-256 학번을 계정 키로 사용합니다. **이 값은 클라이언트의 주장이고 서버가 학교에 직접 확인하지 않습니다.**
- 반환값: `{ token, account, expires_at_ms }`. 임의 256비트 앱 토큰의 수명은 7일이며, 서버에는 토큰 해시·계정 키·만료 시각만 저장합니다. 앱은 토큰을 Android Keystore로 암호화합니다.
- `DELETE /api/dailymath/auth`: Bearer 토큰 하나를 폐기합니다. 앱 연결 해제 때 로컬 토큰을 먼저 지우고 서버 폐기를 시도합니다. 오프라인에서 폐기가 실패하면 원래 만료 시각까지 유효합니다.
- 진행 기록·랭킹 API에는 서버 발급 Bearer 토큰이 필요합니다. 임의의 `X-DailyMath-Account` 헤더로 대상 계정을 바꿀 수 없습니다.

기존 SHA-256 학번 키를 유지하므로 이전 학습 기록은 같은 학번에서 이어집니다. PDF와 필기는 서버 동기화 대상이 아닙니다. 이 인증 변경에 맞는 최신 Android 앱이 필요합니다.

## 학습 기록

`GET /api/dailymath/progress`는 해당 앱 토큰 계정의 기록을 반환합니다. `PUT`은 최대 200개를 한 트랜잭션으로 저장하고 204를 반환합니다.

필드는 `post_id`, `state` (`draft` 또는 `submitted`), `reply_id`, `solved_on`, `updated_at_ms`, `first_submitted_at_ms`입니다. 오래된 요청은 최신 상태를 덮어쓰지 않으며 가장 이른 확인된 제출 시각을 보존합니다. 시각이 없는 과거 기록을 추정하여 채우지 않습니다. `pending`은 앱이 학교에서 확인해야 하므로 동기화 대상에서 제외합니다.

## 스트릭 랭킹

사용자는 학교 댓글에 표시되는 학생 이름·학번·제출 시각의 저장과 랭킹 표시를 승인했습니다. 앱을 쓰지 않는 학생도 댓글 제출 이력이 있으면 포함하며, 제출 이력이 전혀 없는 학생 명단은 수집하지 않습니다.

학교 페이지 조회는 **기기에서만** 합니다. 앱은 전체 HTML에서 문제 제목·번호·날짜와 댓글 작성자·시각만 골라 작은 메타데이터 HTML을 만듭니다. 프로필의 다른 정보, 댓글 본문, PDF, 첨부 주소, 학교 쿠키와 스크립트는 quiz 서버에 전송하지 않습니다. 서버는 클라이언트가 보고한 메타데이터를 신뢰하고 파싱·집계합니다.

- `GET /api/dailymath/ranking`: 저장된 결과와 미수집 문제 번호를 반환합니다.
- 첫 갱신 `POST`: `{ "board_html": "최소 목록 HTML", "continue_scan": false }`. 서버는 문제 목록을 맞추고 최근 3문제·미수집 문제·24시간 이상 지난 과거 문제 1개의 우선순위로 `scan_post_ids`를 반환합니다.
- 앱이 해당 글을 읽은 뒤 `POST`: `{ "replies": [{ "post_id": 18038, "html": "작성자·시각만 있는 HTML" }], "continue_scan": true }`. 최대 8문제씩 반영합니다.
- `has_more`가 true이면 미수집 문제부터 계속합니다. 중간에 실패하거나 화면을 나가도 완료된 문제는 DB에 보존됩니다. 수집된 댓글을 다시 제출해도 복합 기본 키와 최소·최대 시각 병합으로 중복 집계되지 않습니다.
- MySQL named lock은 짧은 DB 갱신 동안만 사용합니다. 학교 네트워크 요청 동안 DB 연결이나 잠금을 잡지 않습니다.
- 첫 전체 집계가 끝날 때까지 불완전한 순위를 공개하지 않습니다. 이후에는 저장된 결과를 먼저 표시하고 새 댓글을 반영합니다.

당일 제출은 **제목에 적힌 문제 날짜의 0시부터 다음 날 자정 직전(Asia/Seoul)**입니다. 제목에서 유효한 날짜를 읽지 못하면 게시판 작성 날짜·시각을 사용합니다. 예를 들어 107일차는 제목이 9/18이고 작성 시각은 9/15이므로 9/18 제출을 인정합니다. 사용자가 확인한 기준이며 앱의 개인 스트릭·달력·제출 색상에도 똑같이 적용합니다. 문제 없는 주말·공휴일은 끊지 않고, 당일 미제출은 자정까지 유예합니다. 해설 날짜는 판정에 사용하지 않습니다.

같은 문제의 중복 게시글은 한 번만 셉니다. 동점은 공동 순위(1, 1, 3)입니다. 동일 학생의 풀이 교체에서는 이미 확인한 최초 제출 시각을 유지하며, 마지막 제출 시각은 별도로 가장 최근 값을 저장합니다. 학교가 삭제한 댓글은 해당 문제를 다시 조회할 때 반영합니다.

응답 필드: `ready`, `updated_at_ms`, `scanned_posts`, `total_posts`, `has_more`, `refreshing`, `scan_post_ids`, `entries`. 항목에는 `rank`, `student_id`, `name`, `streak`, `total_solved`, `last_submitted_at_ms`, `is_me`가 있습니다.

## 저장소와 제한

기존 `dailymath_account_progress`, `dailymath_sessions`와 랭킹 전용 `dailymath_ranking_posts`, `dailymath_ranking_submissions`, `dailymath_ranking_students`, `dailymath_ranking_state`를 사용합니다. 첫 요청 때 없으면 생성하며 기존 퀴즈 테이블은 변경하지 않습니다. 초기 기기별 실험의 `dailymath_progress`는 자동 삭제·이전하지 않습니다.

`published_at_ms`와 `published_on`은 랭킹 판정용 문제 시작 시각·날짜입니다. 제목 날짜를 수정해도 원본 댓글 시각은 남아 있으므로 전체 재수집 없이 재계산합니다. 최초 수집은 문제 107개, 댓글 제출자 87명으로 완료했습니다.

인증 본문은 2 KiB, 진행 기록은 128 KiB, 랭킹은 1 MiB로 제한합니다. 랭킹 한 요청은 최대 8댓글 페이지이며 중복 게시글 번호·빈 자료·과도한 크기는 거절합니다. 요청 제한은 프로세스 내 계정별 분당 30회이므로 여러 인스턴스로 확장할 때는 공유 제한기로 바꿔야 합니다.

이전 서버 직접 조회 방식에서 DNS 및 학교 세션의 서버 인식 문제를 확인했습니다. 현재 인증·랭킹 경로는 학교 서버에 접속하지 않으므로 `DAILYMATH_SCHOOL_IPV4` 설정이 필요 없습니다. 과거 전송·프로필 파서 코드는 회귀 참고용으로 남아 있으며 현재 API에서는 호출하지 않습니다.

검사: `npm run test:dailymath`, `npx tsc --noEmit`, 변경된 파일 ESLint, `npm run build`. 요청·응답 로그에 학생 정보나 인증 정보를 출력하지 않습니다.
