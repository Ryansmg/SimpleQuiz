# DailyMath API

기존 quiz Next.js 서버와 Railway MySQL을 사용합니다. 공개 주소는 `https://minguu.dev`이며 앱에는 `DAILYMATH_API_URL`만 설정합니다. MySQL 연결 정보는 서버의 기존 `MYSQL_URL`에 둡니다. PC에 DB 서버를 설치하지 않습니다.

## 인증과 신뢰 범위

앱 토큰은 서버가 송죽학사 계정을 직접 확인한 뒤 발급합니다. 앱이 보낸 학번이나 HTML을 본인 인증으로 사용하지 않습니다.

- `POST /api/dailymath/auth`: JSON `{ "auto_login_proof": "SHA-256(school_seed), 64자리 소문자 hex" }`. 학교 자동 로그인 프로토콜의 `sKey`에 해당하는 **인증 자격정보**입니다. HTTPS 본문으로만 보내며 URL·로그·DB·서버 캐시에 남기지 않습니다. 원본 seed와 학교 비밀번호는 기기 밖으로 보내지 않습니다.
- 서버는 새 `getSessionKey.do` 세션을 만들고, 해당 challenge와 쿠키로 `autoLogin.do`를 호출합니다. 성공한 서버용 학교 세션의 내정보 페이지에서 실제 학번을 읽어 SHA-256 계정 키를 결정합니다. 세션은 한 번의 토큰 교환 중 메모리에서만 사용합니다. 리다이렉트를 따라가지 않으며 고정 학교 주소 외에는 인증값을 전송하지 않습니다. 학교 프로토콜의 `RETRY` 응답에만 새 challenge로 한 번 다시 인증하고, 네트워크 실패는 재전송하지 않습니다. 전체 교환은 30초 이내로 제한합니다. `NO_SESSION`은 401, 일시적 응답 오류와 로그인 성공 후 프로필 확인 실패는 503으로 구분하며 어느 실패에도 토큰을 발급하지 않습니다.
- 반환값: `{ token, account, expires_at_ms }`. 임의 256비트 앱 토큰의 수명은 7일이며, 서버에는 토큰 해시·계정 키·만료 시각·검증 버전만 저장합니다. 앱은 응답 계정이 로컬 학교 계정과 일치하는지 검사하고 토큰을 Android Keystore로 암호화합니다.
- `DELETE /api/dailymath/auth`: Bearer 토큰 하나를 폐기합니다. 앱 연결 해제 때 로컬 토큰을 먼저 지우고 서버 폐기를 시도합니다. 오프라인에서 폐기가 실패하면 원래 만료 시각까지 유효합니다.
- 진행 기록·랭킹 API는 `verification_version = 1`인 서버 발급 토큰만 허용합니다. 이전 학번 신뢰 방식에서 발급된 토큰은 기본값 0으로 남아 모두 거절됩니다. 앱은 401을 받으면 학교 인증 후 새 토큰을 받아 이어갑니다.

학습 기록과 랭킹 데이터는 삭제하지 않으며 기존 SHA-256 학번 키를 유지합니다. 최신 Android 앱이 필요합니다. 학교 비밀번호 변경이 이미 발급된 앱 토큰을 즉시 폐기하지는 않으며 토큰 만료 후 학교 인증을 다시 수행합니다.

## 학습 기록

`GET /api/dailymath/progress`는 해당 앱 토큰 계정의 기록을 반환합니다. `PUT`은 최대 200개를 한 트랜잭션으로 저장하고 204를 반환합니다.

필드는 `post_id`, `state` (`new`, `draft`, `submitted`, `late`), `reply_id`, `solved_on`, `updated_at_ms`, `first_submitted_at_ms`입니다. 오래된 요청은 최신 상태를 덮어쓰지 않으며 가장 이른 확인된 제출 시각을 보존합니다. 시각이 없는 과거 기록을 추정하여 채우지 않습니다. `pending`은 앱이 학교에서 확인해야 하므로 동기화 대상에서 제외합니다.

## 스트릭·해결 수 랭킹

사용자는 학교 댓글에 표시되는 학생 이름·학번·제출 시각의 저장과 랭킹 표시를 승인했습니다. 앱을 쓰지 않는 학생도 댓글 제출 이력이 있으면 포함하며, 앱에서 늦은 완료만 기록한 학생도 전체 해결 수에 포함합니다. 활동 기록이 전혀 없는 학생 명단은 수집하지 않습니다.

랭킹용 학교 게시판·댓글 조회는 **기기에서만** 합니다. 앱은 전체 HTML에서 문제 제목·번호·날짜와 댓글 작성자·시각만 골라 작은 메타데이터 HTML을 만듭니다. 프로필의 다른 정보, 댓글 본문, PDF, 첨부 주소, 학교 쿠키와 스크립트는 quiz 서버에 전송하지 않습니다. 서버는 학교 인증을 마친 클라이언트가 보고한 메타데이터를 신뢰하고 파싱·집계합니다. 학교 계정 인증은 자료 자체의 위변조까지 검증하는 것은 아닙니다.

- `GET /api/dailymath/ranking`: 저장된 결과와 미수집 문제 번호를 반환합니다.
- 첫 갱신 `POST`: `{ "board_html": "최소 목록 HTML", "continue_scan": false }`. 서버는 문제 목록을 맞추고 최근 3문제·미수집 문제·24시간 이상 지난 과거 문제 1개의 우선순위로 `scan_post_ids`를 반환합니다.
- 앱이 해당 글을 읽은 뒤 `POST`: `{ "replies": [{ "post_id": 18038, "html": "작성자·시각만 있는 HTML" }], "continue_scan": true }`. 최대 8문제씩 반영합니다.
- `has_more`가 true이면 미수집 문제부터 계속합니다. 중간에 실패하거나 화면을 나가도 완료된 문제는 DB에 보존됩니다. 수집된 댓글을 다시 제출해도 복합 기본 키와 최소·최대 시각 병합으로 중복 집계되지 않습니다.
- MySQL named lock은 짧은 DB 갱신 동안만 사용합니다. 학교 네트워크 요청 동안 DB 연결이나 잠금을 잡지 않습니다.
- 첫 전체 집계가 끝날 때까지 불완전한 순위를 공개하지 않습니다. 이후에는 저장된 결과를 먼저 표시하고 새 댓글을 반영합니다.

당일 제출은 **제목에 적힌 문제 날짜의 0시부터 다음 날 자정 직전(Asia/Seoul)**입니다. 제목에서 유효한 날짜를 읽지 못하면 게시판 작성 날짜·시각을 사용합니다. 예를 들어 107일차는 제목이 9/18이고 작성 시각은 9/15이므로 9/18 제출을 인정합니다. 사용자가 확인한 기준이며 앱의 개인 스트릭·달력·제출 색상에도 똑같이 적용합니다. 문제 없는 주말·공휴일은 끊지 않고, 당일 미제출은 자정까지 유예합니다. 해설 날짜는 판정에 사용하지 않습니다.

같은 문제의 중복 게시글은 한 번만 셉니다. 동점은 공동 순위(1, 1, 3)입니다. 동일 학생의 풀이 교체에서는 이미 확인한 최초 제출 시각을 유지하며, 마지막 제출 시각은 별도로 가장 최근 값을 저장합니다. 학교가 삭제한 댓글은 해당 문제를 다시 조회할 때 반영합니다.

응답 필드: `metrics_version`, `ready`, `updated_at_ms`, `scanned_posts`, `total_posts`, `has_more`, `refreshing`, `scan_post_ids`, `entries`. 항목에는 `rank`, `student_id`, `name`, `streak`, `on_time_solved`, `total_solved`, `last_submitted_at_ms`, `last_solved_at_ms`, `is_me`가 있습니다.

## 저장소와 제한

기존 `dailymath_account_progress`, `dailymath_sessions`, 학생 표시용 `dailymath_student_profiles`와 랭킹 전용 `dailymath_ranking_posts`, `dailymath_ranking_submissions`, `dailymath_ranking_students`, `dailymath_ranking_state`를 사용합니다. 첫 요청 때 없으면 생성하며 기존 퀴즈 테이블은 변경하지 않습니다. 초기 기기별 실험의 `dailymath_progress`는 자동 삭제·이전하지 않습니다.

`published_at_ms`와 `published_on`은 랭킹 판정용 문제 시작 시각·날짜입니다. 제목 날짜를 수정해도 원본 댓글 시각은 남아 있으므로 전체 재수집 없이 재계산합니다. 최초 수집은 문제 107개, 댓글 제출자 87명으로 완료했습니다.

인증 본문은 2 KiB, 진행 기록은 128 KiB, 랭킹은 1 MiB로 제한합니다. 랭킹 한 요청은 최대 8댓글 페이지이며 중복 게시글 번호·빈 자료·과도한 크기는 거절합니다. 인증은 학교 요청 전 전체 분당 30회, 인증 후 및 나머지 API는 계정별 분당 30회로 제한합니다. 프로세스 내 제한이므로 여러 인스턴스로 확장할 때는 공유 제한기로 바꿔야 합니다.

Railway의 학교 DNS 조회가 실패하는 환경에서는 독립적으로 확인한 학교 IPv4를 `DAILYMATH_SCHOOL_IPV4`로 설정합니다. 원래 학교 Host·TLS SNI·인증서 검증은 유지합니다. 학교 연결은 새 HTTP/1.1 연결을 사용하며 자동 재시도하지 않습니다. 앱 쿠키를 재사용하지 않고 서버 위치에서 세션을 새로 만듭니다.

검사: `npm run test:dailymath`, `npx tsc --noEmit`, 변경된 파일 ESLint, `npm run build`. 요청·응답 로그에 학생 정보나 인증 정보를 출력하지 않습니다.

## 해결 수 집계와 호환성

- 스트릭은 기존 연속 당일 제출 기준을 유지합니다. 당일 해결 수는 문제 날짜 안에 학교 댓글로 제출한 고유 문제 수, 전체 해결 수는 여기에 늦은 학교 제출과 앱의 늦은 완료 기록을 합친 고유 문제 수입니다. 중복 게시글·재제출·학교와 앱의 중복 기록은 한 번만 셉니다. 앱 완료 기록만으로 당일 해결이나 스트릭을 얻지 않습니다.
- 앱은 같은 응답으로 스트릭 / 당일 해결 / 전체 해결 탭을 정렬합니다. 동점은 공동 순위이며, 스트릭·당일 해결은 마지막 학교 제출 시각, 전체 해결은 마지막 제출·완료 시각 내림차순입니다. 시각까지 같으면 학번을 사용합니다. 탭 전환은 추가 요청을 만들지 않고 기존 10분 캐시·수동 새로고침 규칙을 유지합니다.
- 진행 기록 PUT은 기존 배열과 새 `{ records: [...], profile: { student_id, name } }` 본문을 모두 받습니다. 프로필은 이미 학교 인증된 토큰의 계정 해시와 학번이 일치할 때만 저장합니다. 토큰 인증 방식은 바꾸지 않습니다. 앱은 학교 내정보에서 학번·이름만 추출해 기기에 암호화 캐시하고, 학교 댓글이 없는 앱 참가자의 표시 정보로 보냅니다.
- 앱의 늦은 완료는 기존 진행 기록으로 동기화합니다. 완료 시 동기화를 시도하고, 실패한 로컬 기록은 다음 동기화까지 보존합니다. 랭킹 갱신 전에 본인 진행 기록을 동기화하며 학교 댓글에는 업로드하지 않습니다.
- 랭킹 테이블에 `on_time_solved`, `last_solved_at_ms`와 집계 버전 `metrics_version`을 추가합니다. 기존 결과는 첫 조회에서 저장된 문제·댓글·완료 기록으로 버전 2 집계로 이전하며 학교 전체 재수집은 하지 않습니다. 이때 기존 랭킹 갱신과 같은 DB 잠금을 사용합니다. 앱은 구형 집계 결과를 해결 수 0으로 표시하지 않습니다.
## 과거 문제 PDF 날짜 보정 (집계 버전 3)

2026년 1~34일차의 제목에는 문제 날짜가 없어 게시글의 일괄 작성 시각으로 집계되고 있었습니다. 로컬에서 원본 PDF 34개의 첫 페이지 날짜를 추출하고 첨부파일명 날짜와 일치함을 확인했습니다. `docs/dailymath-problem-dates-2026.json`에 문제 ID·연도·일차·날짜·원본 파일명·SHA-256을 보관하고, 여기서 생성한 `lib/dailymath-problem-dates.ts`를 사용합니다. PDF 원본·학생 정보는 이 데이터에 포함하지 않습니다.

확인된 문제는 PDF 날짜를 우선합니다. 게시글 ID·연도·일차가 모두 일치할 때만 적용하며 그 외 문제는 제목 날짜와 기존 작성 시각 대체 규칙을 유지합니다. 앱도 같은 보정표를 사용합니다. 갱신 시 구형 앱이 보낸 글 제목에도 서버가 직접 보정을 적용합니다.

`metrics_version = 3`으로 올리고 기존 저장된 문제 날짜와 랭킹을 최초 조회 때 같은 잠금/트랜잭션 안에서 보정합니다. 기존 원본 댓글 시각으로 다시 계산하므로 학교 전체 재수집은 필요 없습니다. 실제 댓글·개별 학습 기록은 변경하지 않습니다. 배포 전 읽기 전용 비교에서 당일 해결 인정이 918건 증가하고, 전체 해결 수와 현재 스트릭은 바뀌지 않았습니다.

## 필기 자동 동기화

기존 학교 인증 앱 토큰을 사용한 `/api/dailymath/ink` GET(버전 목록) 및 `/api/dailymath/ink/{postId}` GET/PUT을 추가했습니다. MySQL `dailymath_ink` 테이블에 계정·문제별 gzip 선 데이터와 PDF/필기 SHA-256, revision을 저장합니다. PDF는 저장하지 않습니다. PUT은 트랜잭션/행 잠금으로 기준 revision을 검사하며 충돌은 409, 같은 내용 재전송은 기존 revision을 반환합니다. 메타데이터 목록에는 본문이 포함되지 않습니다.

한 문서는 압축 2MiB/해제 16MiB, 100만 좌표, 계정은 256MiB/5000문서로 제한합니다. 압축 해제 크기, 좌표, 해시를 검사합니다. 필기 API는 계정별 별도 분당 30회 한도를 사용합니다. 앱은 문제별 5초 유휴 업로드, 요청 간격 3초, 실패 시 지수 백오프를 적용합니다. `scripts/test-dailymath-ink.cjs`에 압축 제한·잘못된 좌표·충돌·중복 요청 테스트가 있습니다.
